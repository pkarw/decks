09 — Autonomous skills

om-auto-* goes wild.

om-auto-review-pr Every PR reviewed against CODE_REVIEW.md before a human ever opens it.
om-auto-create-pr Ralph Wiggum loops: keep going until the checks are green.
om-auto-spec-writing Specs authored to the same shape the whole factory reads.
om-auto-qa-pr agent-browser runs the PR, posts test cases, integration results and screenshots as comments — each in its own testcontainers env.
Fire and forget. Get the next task. Repeat.

11 — Best practices

One pipeline, many agents.

01 We go wild on worktrees and subagents — parallel by default.
02 All of them share one gh strategy, one labeling strategy, one set of checks.
03 Skills split into references and subtasks, cross-reference-free, skills.sh compatible.
04 Every run auto-writes .ai/runs and .ai/lessons-learned, and parks QA artifacts per check.
/ om-setup-agentic-pipeline
agentic.config.json SDLC.md CODE_REVIEW.md BACKWARD_COMPATIBILITY.md
Four files that make twenty parallel agents behave like one team.
12 — Orchestration

Divide and conquer
with Cezar.

Running om-auto-* is cool. Running twenty in parallel is not. Cezar is our parallel coding orchestrator — MIT, native skills, GitHub-first.

$ npx cezar-cli

It runs on my VPS. I coordinate tasks from my phone all day — and because of how the skills work, the interface I use most is GitHub itself.

github.com/open-mercato/cezar
